МАНУЛ ЧАТ — SYNLOGY CONTAINER MANAGER
====================================

Эта папка подготовлена для Synology DSM 7.2 / Container Manager.

Файлы:
    Dockerfile
    compose.yaml
    requirements.txt
    app.py
    static\
    data\

ВАЖНО
=====
В compose.yaml приложение работает в режиме:

    APP_ENV=production

Это значит, что session cookie имеет флаг Secure.
Вход в чат должен выполняться через HTTPS reverse proxy Synology.

Контейнер НЕ публикует приложение на все сетевые интерфейсы NAS.
Порт проброшен только на localhost NAS:

    127.0.0.1:18080 -> container:8000

Поэтому снаружи должен использоваться Reverse Proxy DSM:

    https://chat.example.ru
             |
             v
    Synology Reverse Proxy
             |
             v
    http://127.0.0.1:18080
             |
             v
        manul-chat


УСТАНОВКА ЧЕРЕЗ CONTAINER MANAGER
=================================

1. В DSM установите пакет:
       Container Manager

2. Создайте общую папку, например:
       docker

3. В File Station создайте:
       /docker/manul-chat

4. Распакуйте содержимое этого архива туда.
   В папке должны лежать непосредственно:
       app.py
       Dockerfile
       compose.yaml
       requirements.txt
       static
       data

5. Если хотите перенести существующую базу и картинки,
   ДО первого запуска скопируйте:
       старый data/messenger.db
       старый data/uploads/*
   в:
       /docker/manul-chat/data/

6. Откройте:
       Container Manager -> Проект (Project) -> Создать

7. Выберите:
       Создать docker-compose.yml / существующий compose-проект
   и укажите папку:
       /docker/manul-chat

   Файл проекта:
       compose.yaml

8. Выполните сборку и запуск проекта.

9. Откройте журнал контейнера manul-chat.
   Если база новая, там будет выведен:
       Логин: admin
       Пароль: случайно сгенерированный пароль

   Сохраните этот пароль.


REVERSE PROXY DSM
=================

Путь в DSM 7:
    Панель управления
      -> Портал входа
      -> Дополнительно
      -> Обратный прокси-сервер

Создайте правило.

Источник:
    Протокол: HTTPS
    Имя хоста: ваш домен, например chat.example.ru
    Порт: 443

Назначение:
    Протокол: HTTP
    Имя хоста: 127.0.0.1
    Порт: 18080

ВАЖНО ДЛЯ ЧАТА
==============
В правиле Reverse Proxy:
    Пользовательский заголовок
      -> Создать
      -> WebSocket

Synology автоматически добавит необходимые заголовки
Upgrade / Connection.

Без этого обычные страницы могут открываться,
но сообщения в реальном времени / онлайн-статус работать не будут.


HTTPS-СЕРТИФИКАТ
================

В DSM:
    Панель управления
      -> Безопасность
      -> Сертификат

Добавьте сертификат Let's Encrypt для вашего домена
и назначьте его правилу/домену Манул Чат.


ПЕРЕНОС СУЩЕСТВУЮЩЕЙ БАЗЫ
==========================

Контейнер хранит постоянные данные снаружи:

    /docker/manul-chat/data
          |
          +-- messenger.db
          +-- uploads/

В контейнере это:
    /app/data

Поэтому пересборка или обновление контейнера
НЕ удаляет сообщения и картинки.

Перед обновлением всё равно рекомендуется сделать копию:
    data/messenger.db
    data/uploads/


ОБНОВЛЕНИЕ ПРОГРАММЫ
====================

1. Сделайте резервную копию папки data.
2. Замените:
       app.py
       static/
       requirements.txt
       Dockerfile
3. НЕ удаляйте data/.
4. В Container Manager пересоберите проект.


ПРОВЕРКА
========

В Container Manager контейнер должен иметь состояние Healthy.

Прямой URL:
    http://127.0.0.1:18080

доступен только самому NAS.

Пользовательский URL:
    https://ваш-домен/


ПОЧЕМУ ОДИН КОНТЕЙНЕР / ОДИН ПРОЦЕСС
====================================

Сейчас онлайн-статус и WebSocket-подключения хранятся
в памяти процесса Python. Поэтому не запускайте несколько
реплик manul-chat и не добавляйте несколько Uvicorn workers.

Для текущего небольшого мессенджера:
    1 контейнер
    1 Python/Uvicorn процесс

— правильная конфигурация.
